# Backend integration

## Responsibilities

`contracts/openapi.yaml` defines the HTTP formats. `shared/api/generated/schema.ts` is generated by `openapi-typescript`. The helper types in `shared/api/types.ts` require exactly one area selector for historical queries. The contracts in `prevention-demo` are presentation models for a prototype and must not be used as backend formats.

`shared/api/http.ts` handles URLs, parameters, JSON, a 15-second timeout, cancellation, and `ApiError`. Each feature's services define its operations and domain rules. `app/api.ts` configures the instances using the public environment URL. Components should receive data and state or use hooks; they should not construct URLs or import fixtures to replace failed API responses.

Generated types check consumers at compile time. The transport rejects invalid JSON but does not perform full schema validation in production. `validate_contract.py --server ...` can validate actual responses from routes without required parameters against the contract.

## Using services in a screen

This example assumes a component in `src/features/history/components/`. When connecting the application, query `/history/meta` once during initial composition and share coverage, limits, biomes, and harmonization status with the screens. Do not reuse the fixtures' cutoff date as a backend limit.

```tsx
import { useCallback } from "react";
import { historyApi } from "../../../app/api";
import { useApiResource } from "../../../shared/api/useApiResource";

const loadCalendar = useCallback(
  (signal: AbortSignal) => historyApi.getCalendar(
    { biome: "Pantanal", start: "2020-08-01", end: "2020-10-31", granularity: "month" },
    { signal },
  ),
  [],
);
const calendar = useApiResource(loadCalendar);
// Handle idle, loading, error, and success; on success, buckets=[] is an empty result.
```

Keep the loader stable with `useCallback` and include the filters it uses in the dependencies. Pass `null` to disable the query. Use `reload()` to retry. The hook cancels stale requests when filters change or the component unmounts and never uses demonstration data as a fallback.

For a rectangular area, use `bboxSelector([west, south, east, north])`. For polygons, send WGS84 GeoJSON with `historyApi.createArea({ geometry })`, then query using `{ area_id: result.area_id }`. The demo map's projected coordinates are not GeoJSON; implement the geographic conversion before connecting them to this route.

## Scientific conventions and states

- The historical unit is `fire_cell_days`: 0.1° cells with fire on a UTC day. Do not represent it as burned area or hotspot counts.
- Do not add MODIS and VIIRS values together. The backend computes their union and harmonization.
- `null` means missing data, while `0` means an observation with no fire. `calendarValue` preserves this distinction. Also retain the `low/high` interval when displaying harmonized estimates.
- `start` and `end` are inclusive UTC dates. Historical weeks are blocks of the year defined by the contract, not ISO weeks.
- `provisional: true` identifies NRT data and must remain visible.
- Climatology, anomaly, season, and trend return `{ data, requestedSeries, effectiveSeries, fallback }`. Only HTTP 409 for a harmonized request triggers a new MODIS query. Display this fallback explicitly. Calendar and map responses preserve null harmonized fields and do not accept a `series` parameter.
- HTTP 400/422 requires reviewing the filters; 404 may indicate an expired area; 413 requires reducing the area or period. None of these should become a zero count.
- VIIRS trends across years reflect changes in satellite coverage. Do not present the MODIS fallback as a harmonized series.
- Live event confidence ranges from 0 to 1 and is a heuristic, not a calibrated risk probability.

## Live stream

`subscribeFires` uses the named events `snapshot` and `pulse` and returns a cleanup function. Return that function from the `useEffect` cleanup. The browser reconnects automatically; `open` and `error` allow the connection state to be updated. Invalid JSON messages are forwarded to `error`.

Replace the state with the received `snapshot`. For pulses, use `applyPulse(previous, pulse)`: it updates records by `fire_id`, adds new events, and removes the identifiers in `removed`. The contract defines no stream filters; filter locally or query `/fires/live` for filtered searches. Close the connection when leaving the screen to avoid accumulating subscribers.

## Which page reads what

The area (biome or lon/lat box) and the period are shared by Overview, Fire Map, Historical Analysis and Burning Calendar. `/history/meta` is read once by `App` and passed down; the default period is the last 30 days of the record.

| Page | Routes |
| --- | --- |
| Overview | `/history/calendar` (KPIs, chart), `/history/anomaly` (period vs normal), `/history/map` + `/fires/live` (map), `/forecast` (summary card), `/fires/live` (table) |
| Fire Map | `/history/map`, `/fires/live` |
| Burning Calendar | `/history/calendar` (day and week), `/history/climatology`, `/history/anomaly`, `/history/season`, `/history/trend` |
| Historical Analysis | `/history/calendar` (KPIs, VIIRS yearly totals), `/history/trend` (harmonized and MODIS), `/history/meta` (method) |
| Anomaly Alerts | `/history/calendar` (month) and `/history/climatology` (month) for every biome |
| Risk Forecast | `/forecast`, `/forecast/model` |
| Alert Center | none: the backend has no alert routes, and the page says so |
| Data Sources | `/status`, `/history/meta` |
| Sidebar | `/status` |

## What the backend does not provide yet

Each item below is visible in the front as a missing feature or a slow page, never as made-up data.

1. **Forecast without `FIRMS_MAP_KEY`**: `/forecast` answers 503 and FIRMS NRT live fires are off until the key is set on the server. Only GOES ABI feeds the live layer then.
2. **No national area**: Brazil as a box has 160,000 cells, above `max_area_cells` (50,000), so there is no "all of Brazil" view. A `country=BR` area (or a raised limit with precomputed national series) is needed.
3. **No named administrative areas**: only biomes, boxes and drawn polygons. States, municipalities, conservation units and indigenous lands would need a catalogue (for example IBGE boundaries) with ids usable as `area_id`.
4. **No alert routes**: nothing issues, stores or delivers alerts, or tracks read state. Alert Center and the notification bell stay empty.
5. **No server-side anomaly scan**: Anomaly Alerts sends 12 requests (calendar and climatology for 6 biomes) and takes about 20 s. A route such as `/history/anomalies?year=&granularity=month` over all biomes (or areas) would do it in one call.
6. **Slow analytics**: climatology, anomaly, season and trend take about 2 s each, recomputed per request. Caching or precomputed normals per biome would make Overview and Burning Calendar load in about a second.
7. **No interval on period totals**: `/history/anomaly` always returns `value_interval: null`, and calendar intervals cannot be added across buckets. Totals that include VIIRS-estimate days need an interval computed on the server.
8. **Map size limit**: `/history/map` answers 413 above 20,000 cells (for example Amazon over a full year: 25,473). A coarser aggregation level or tiles are needed for large areas and long periods.
9. **Live fires not filtered by area**: `/fires/live` and `/detections/recent` accept only `bbox`, not `biome` or `area_id`, so the live table shows every fire in the worker's window.
10. **Forecast not summarised by area**: `/forecast` lists cells only. A per-biome or per-area daily summary (for example expected fire cells) is needed for a regional view, instead of the front guessing which cells fall in a biome.

Automated service tests use simulated transport; end-to-end validation requires a running backend.
